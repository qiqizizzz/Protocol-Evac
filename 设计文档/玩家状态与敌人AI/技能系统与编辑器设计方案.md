# Protocol_Evac 技能系统与编辑器设计方案

## 一、设计结论

当前技能系统采用“运行时数据驱动 + 编辑器工具辅助”的路线：

```text
运行时
└─ 不依赖 Odin、NaughtyAttributes 或自定义 EditorWindow

编辑期
├─ 第一阶段：NaughtyAttributes + ScriptableObject 列表
├─ 第二阶段：自研轻量 Skill Timeline EditorWindow
└─ 第三阶段：按需要评估节点图或更完整的可视化工具
```

核心原则：

```text
Skill Data 是权威数据
Editor 只是编辑 Skill Data 的工具
战斗运行时只读取 Skill Data
任何编辑器插件都不能成为战斗逻辑依赖
```

本方案暂不采用 Unity Timeline / Playables 作为核心技能运行时。Timeline 更适合演出、镜头和动画编排；本项目技能需要普攻段数、取消窗口、命中帧、位移事件和后续连段规则，使用自有数据结构更容易调试和演进。

## 二、系统边界

### 1. HFSM 与 Skill 的关系

HFSM 负责玩家所处的宏观状态：

```text
Grounded
Airborne
Action
Skill
Disabled
```

Skill System 负责技能内部时间轴：

```text
NormalAttack
SpecialSkill
Ultimate
```

两者边界如下：

| 模块 | 职责 |
| --- | --- |
| `PlayerSkillState` | 进入技能大分支、承载技能状态生命周期 |
| `PlayerNormalAttackState` | 消费普攻输入、锁移动、请求播放 `Base Layer.Skill.normalAttack01` |
| Skill 数据 | 描述技能段落、持续时间和事件窗口 |
| Skill Runner | 根据当前时间推进技能事件 |
| Transition Rules | 判断能不能进入技能、技能结束后回到哪个状态 |

`Dodge` 不放入 Skill。闪避属于 `ActionDodge`，继续由 Action 分支承载。

### 2. 输入与技能类型

输入层使用语义输入，不使用键位命名：

```text
PlayerBufferedInputType
├─ Jump
├─ NormalAttack
├─ SpecialSkill
├─ Ultimate
└─ Dodge
```

技能类型保持同一组语义：

```text
PlayerSkillType
├─ NormalAttack
├─ SpecialSkill
└─ Ultimate
```

不要引入 `Slot` 命名。除非后续真的存在“技能槽位 / 装备槽位”数据结构，否则 `Slot` 会混淆键位、类型和数据索引。

## 三、数据结构方向

第一阶段建议先只做最小普攻纵切，不急着创建完整数据层。

当前已经有：

```text
PlayerNormalAttackConfigSO
├─ NormalAttackDuration
├─ NormalAttackBufferTime
└─ LockMovement
```

后续稳定后，再升级到通用 Skill 数据：

```text
PlayerSkillDataSO
├─ SkillType
├─ CooldownTime
└─ Steps
   ├─ Step 1
   ├─ Step 2
   └─ Step 3
```

单段技能数据建议：

```text
PlayerSkillStepData
├─ Duration
└─ Events
```

事件数据建议：

```text
PlayerSkillEventDataBase
├─ StartTime
├─ EndTime
└─ EventKind
```

事件类型先按真实需要逐步补，不提前铺满：

```text
Hitbox       命中判定
Motion       技能位移
CancelWindow 取消窗口 / 连段窗口
Vfx          特效触发
Invincible   无敌窗口
```

`PlayerSkillPhase` 暂时不急着建。当前阶段用 State 生命周期和 `DurationTimer` 就能跑通普攻第一版；等 Skill Runner 真正接管 Cast / Active / Recovery 时，再决定是否需要 Phase。

## 四、编辑器路线

### 第一阶段：NaughtyAttributes + Inspector 列表

目标是低成本把数据结构打磨清楚。

适合做：

```text
分组显示
条件显示
只读字段
按钮测试
可重排事件列表
```

不在这一阶段做：

```text
时间轴拖拽
多轨道缩放
事件块框选
复制粘贴事件
动画预览
```

原因是技能数据结构尚未稳定，过早造 Timeline 编辑器会把工具写死在临时字段上。

### 第二阶段：自研 Skill Timeline EditorWindow

当 `PlayerSkillDataSO / Step / Event` 稳定后，再做专用窗口。

窗口目标：

```text
左侧：技能和段落列表
中间：时间轴轨道
右侧：选中事件的 Inspector
底部：当前时间、缩放、吸附、播放预览按钮
```

最小功能：

```text
1. 显示时间刻度
2. 显示多条事件轨道
3. 拖拽事件块修改 StartTime / EndTime
4. 点击事件块选中并编辑参数
5. 支持 Undo / Redo
6. 保存回 ScriptableObject
```

推荐技术：

```text
EditorWindow
UI Toolkit 或 IMGUI
SerializedObject / SerializedProperty
Undo.RecordObject
EditorUtility.SetDirty
```

运行时不得引用 EditorWindow 或任何 `UnityEditor` 命名空间。

### 第三阶段：节点图评估

只有出现这些需求时，才考虑节点图：

```text
技能分支
条件连段
派生技能
多路径释放
复杂状态选择
```

可评估方案：

```text
xNode
Unity Graph Toolkit
自研 GraphView / UI Toolkit 节点图
```

节点图不替代 Timeline。节点图表达“分支关系”，Timeline 表达“时间事件”。

## 五、推荐目录

运行时代码建议：

```text
Assets/Scripts/Module/Player/Skill/
├─ PlayerSkillType.cs
├─ Data/
├─ Event/
└─ Core/
```

编辑器代码建议放在 Editor 目录，避免进入运行时程序集：

```text
Assets/Scripts/Module/Player/Skill/Editor/
├─ PlayerSkillDataSOEditor.cs
└─ PlayerSkillTimelineWindow.cs
```

如果后续 Skill 需要被 Enemy 复用，再考虑抽到：

```text
Assets/Scripts/Module/Combat/Skill/
```

当前阶段不要提前抽共享模块。

## 六、落地顺序

### 阶段 1：普攻状态纵切

```text
1. 完成 PlayerSkillState
2. 完成 PlayerNormalAttackState
3. 接入 PlayerSkillTransitionRules
4. 接入 PlayerSkillAnimRules
5. 验证 Base Layer.Skill.normalAttack01 能从起点播放
6. 验证普攻结束后回 GroundedIdle / GroundedMove / AirborneFall
```

本阶段不做：

```text
伤害
连段
取消窗口
SkillDataSO
Timeline Editor
```

### 阶段 2：普攻段落数据

```text
1. 创建 PlayerSkillDataSO
2. 创建 PlayerSkillStepData
3. 用数据替换 PlayerNormalAttackConfigSO 的固定时长
4. 支持普攻第 1 段、第 2 段、第 3 段
```

### 阶段 3：事件数据

```text
1. 创建 CancelWindow 事件
2. 创建 Motion 事件
3. 创建 Hitbox 事件
4. 创建 Vfx 事件
5. 由 Skill Runner 统一按时间触发事件
```

### 阶段 4：编辑器增强

```text
1. 用 NaughtyAttributes 优化 Inspector
2. 数据结构稳定后创建 Skill Timeline EditorWindow
3. 支持事件拖拽、缩放、选中、Undo
```

## 七、当前未决问题

需要后续确认的问题：

```text
1. SpecialSkill 和 Ultimate 的动画路径命名
2. 普攻是否允许移动输入影响朝向
3. 普攻期间是否允许 Dodge 取消
4. 普攻连段窗口是事件数据控制，还是先用 Step 固定字段
5. Hitbox 第一版是用已有碰撞体，还是先只打日志验证
```

当前已确认：

```text
NormalAttack 动画路径：Base Layer.Skill.normalAttack01
Dodge 不进入 Skill
普攻属于 Skill
第一版不引入 Odin
第一版可使用 NaughtyAttributes 辅助 Inspector
```
