# Protocol_Evac 技能系统与编辑器设计方案

## 一、设计结论

当前技能系统采用“运行时数据驱动 + 编辑器工具辅助”的路线：

```text
运行时
├─ 战斗执行只读取 Skill Config 与 Step
└─ 不调用 UnityEditor、EditorWindow 或编辑器反射 API

编辑期
├─ 第一阶段：建立 Skill Config / Step 数据契约
├─ 第二阶段：使用 UI Toolkit 自研 Skill EditorWindow
├─ 第三阶段：补充时间轴交互、动画采样与 Hitbox 预览
└─ 第四阶段：按真实分支需求评估节点图
```

核心原则：

```text
Skill Data 是权威数据
Editor 只是编辑 Skill Data 的工具
战斗运行时只读取 Skill Data
任何编辑器插件都不能成为战斗逻辑依赖
```

本方案暂不采用 Unity Timeline / Playables 作为核心技能运行时。Timeline 更适合演出、镜头和动画编排；本项目技能需要普攻段数、取消窗口、命中帧、位移事件和后续连段规则，使用自有数据结构更容易调试和演进。

当前项目使用 Unity `2022.3.62f3`。普通 Inspector 采用 Tri Inspector `1.15.1` 提供分组、折叠、条件显示和列表交互；专用技能编辑器仍采用 Unity 内置的 UI Toolkit、`SerializedObject` / `SerializedProperty`、Undo API 和 `AnimationMode`，不把 Tri Inspector 作为技能时间轴或运行时逻辑依赖。

## 二、系统边界

### 1. HFSM 与 Skill 的关系

HFSM 负责玩家所处的宏观状态：

```text
Grounded
Airborne
Action
Skill
Disabled
```

Skill System 负责技能内部时间轴：

```text
NormalAttack
SpecialSkill
Ultimate
```

两者边界如下：

| 模块 | 职责 |
| --- | --- |
| `PlayerSkillState` | 进入技能大分支、承载技能状态生命周期 |
| `PlayerNormalAttackState` | 消费普攻输入、锁移动、请求播放 `Base Layer.Skill.normalAttack01` |
| Skill 数据 | 描述技能段落、持续时间和事件窗口 |
| `PlayerSkillController` | 根据当前时间推进技能段落与事件，并把执行请求交给对应运行时模块 |
| Transition Rules | 判断能不能进入技能、技能结束后回到哪个状态 |

`Dodge` 不放入 Skill。闪避属于 `ActionDodge`，继续由 Action 分支承载。

### 2. 输入与技能类型

输入层使用语义输入，不使用键位命名：

```text
PlayerBufferedInputType
├─ Jump
├─ NormalAttack
├─ SpecialSkill
├─ Ultimate
└─ Dodge
```

技能类型保持同一组语义：

```text
PlayerSkillType
├─ NormalAttack
├─ SpecialSkill
└─ Ultimate
```

不要引入 `Slot` 命名。除非后续真的存在“技能槽位 / 装备槽位”数据结构，否则 `Slot` 会混淆键位、类型和数据索引。

## 三、数据结构方向

当前正式结构采用一份技能配置与一组技能段落，不再为动画、伤害和窗口维护按索引对齐的并行数组：

```text
AbilityConfigSO
└─ StepValues
   ├─ Step 1
   ├─ Step 2
   └─ Step 3

PlayerNormalAttackConfigSO : AbilityConfigSO
├─ NormalAttackBufferTime
├─ LockMovement
└─ NormalAttackExitBlendDuration
```

`AbilityConfigSO` 是 Player 与 Enemy 共同依赖的通用能力配置；`PlayerNormalAttackConfigSO` 只保留普攻输入和状态退出所需的适配参数，不再重复保存状态动画段落。

单段技能数据第一版固定为：

```text
AbilityStepData
├─ BeginAnimationClip / BeginDuration / BeginUseRootMotion / BeginCanEndEarly
├─ RecoveryAnimationClip / RecoveryDuration / RecoveryUseRootMotion / RecoveryCanEndEarly
├─ ShowWeapon
├─ UseStepAdvanceWindow / StepAdvanceWindowTrack
└─ UseHitWindow / BeginHitWindowTrack
```

`StepAdvanceWindow` 表示通用的下一段推进窗口。Player 的 `PlayerSkillTimeline` 将其解释为连段推进条件；通用数据层不继承“Combo”或输入缓存语义。

窗口时间范围由 `AbilityWindowTrackBaseSO` 及其强类型轨道保存，`AbilityStepData` 只绑定对应轨道资产。命中、阶段推进和无敌窗口分别保留自己的业务数据，不在段落中重复保存时间区间。

状态动画段落阶段统一使用 `AbilityStepPhase.Begin / Recovery`。Player 只在自己的 Context、动画写入和时间轴中消费该枚举。

## 四、编辑器路线

### 第一阶段：数据契约与普通 Inspector 验证

目标是先确认 `AbilityConfigSO / AbilityStepData` 能完整表达三段普攻，不先实现时间轴交互。

适合做：

```text
创建三段普攻数据
配置动画、持续时间和根运动
配置独立的 HitWindow 与 StepAdvanceWindow
验证序列化、反序列化和运行时读取
建立非法时间、空动画与非法伤害的校验规则
```

不在这一阶段做：

```text
时间轴拖拽
多轨道缩放
事件块框选
复制粘贴事件
动画预览
```

原因是技能数据结构尚未稳定，过早造 Timeline 编辑器会把工具写死在临时字段上。Tri Inspector 只负责普通 Inspector 的分组、折叠和条件显示，不定义运行时架构。

### 第二阶段：UI Toolkit Skill EditorWindow

当 `AbilityConfigSO / AbilityStepData` 稳定后，由通用 Ability Composer 负责动画、事件和窗口编辑，不再创建 Player 专属技能编辑器。

窗口目标：

```text
左侧：技能和段落列表
中间：时间轴轨道
右侧：选中事件的 Inspector
底部：当前时间、缩放、吸附、播放预览按钮
```

最小功能：

```text
1. 显示时间刻度
2. 显示多条事件轨道
3. 拖拽窗口块修改 Step 中对应的开始与结束时间
4. 点击窗口块选中并编辑 Step 参数
5. 支持 Undo / Redo
6. 保存回 ScriptableObject
```

推荐技术：

```text
EditorWindow
UI Toolkit ListView
自定义 VisualElement 时间轴
SerializedObject / SerializedProperty
Undo.RecordObject
EditorUtility.SetDirty
```

运行时不得引用 EditorWindow 或任何 `UnityEditor` 命名空间。

### 第三阶段：预览与高可用交互

数据编辑与基础拖拽稳定后，再增加：

```text
时间轴缩放、平移与帧吸附
事件复制、粘贴、批量移动
动画播放头与 AnimationMode 采样
场景中的 Hitbox 范围预览
统一错误列表与定位
快捷键和选择状态恢复
```

### 第四阶段：节点图评估

只有出现这些需求时，才考虑节点图：

```text
技能分支
条件连段
派生技能
多路径释放
复杂状态选择
```

可评估方案：

```text
xNode
Unity Graph Toolkit
自研 GraphView / UI Toolkit 节点图
```

节点图不替代 Timeline。节点图表达“分支关系”，Timeline 表达“时间事件”。

## 五、推荐目录

运行时代码建议：

```text
Assets/Scripts/Tools/AbilityComposer/Data/
├─ Ability.Data.asmdef
├─ AbilityConfigSO.cs
├─ AbilityStepData.cs
├─ AbilityStepPhase.cs
└─ Window/

Assets/Scripts/Module/Player/Skill/
├─ PlayerSkillType.cs
├─ Data/PlayerNormalAttackConfigSO.cs
└─ Core/
   ├─ PlayerSkillController.cs
   └─ PlayerSkillTimeline.cs
```

通用 `Data/` 只放配置资产、可序列化段落、窗口轨道和运行时元数据，不依赖 `UnityEditor`。Player 的运行时推进、输入缓存、开窗和关窗行为继续归 `Core/PlayerSkillController` 与 `PlayerSkillTimeline`。

命名空间与目录保持一致：

```text
Module.Player.Skill
Module.Player.Skill.Data
Module.Player.Skill.Core
Module.Ability.Data
Module.Ability.Data.Window
```

编辑器代码统一放在独立目录，避免进入运行时程序集：

```text
Assets/Scripts/Tools/AbilityComposer/Editor/
├─ Tools.AbilityComposer.Editor.asmdef
├─ Preview/
├─ Selection/
├─ View/Left/
├─ View/Center/
└─ View/Right/
```

Player 与 Enemy 已共享 `AbilityConfigSO / AbilityStepData / AbilityStepPhase`；输入、HFSM、BT、冷却与执行控制器仍留在各自模块，不继续向通用层提取。

## 六、落地顺序

### 阶段 1：普攻状态纵切

```text
1. 完成 PlayerSkillState
2. 完成 PlayerNormalAttackState
3. 接入 PlayerSkillTransitionRules
4. 接入 PlayerSkillAnimRules
5. 验证 Base Layer.Skill.normalAttack01 能从起点播放
6. 验证普攻结束后回 GroundedIdle / GroundedMove / AirborneFall
```

本阶段不做：

```text
伤害
连段
取消窗口
SkillDataSO
Timeline Editor
```

### 阶段 2：统一 Skill 配置契约

```text
1. 创建 AbilityConfigSO
2. 创建 AbilityStepData
3. 让 PlayerNormalAttackConfigSO 继承 AbilityConfigSO
4. 将三段普攻从 PlayerStateClipData 迁移为唯一的 StepValues
5. 通过普通 Inspector 确认三段普攻数据可完整序列化
```

### 阶段 3：运行时技能控制

```text
1. 创建 PlayerSkillController
2. 由 PlayerNormalAttackState 读取通用 Step 段落与推进窗口
3. 由 PlayerSkillController 推进当前段与事件边界
4. 将 Step 命中窗口桥接到 CombatHitbox.Open / Close
5. 完成一段普攻、一个目标、一个窗口、一次伤害的 Play Mode 验证
```

### 阶段 4：技能编辑器基础版

```text
1. 创建 Editor 专用程序集与 PlayerSkillEditorWindow
2. 完成技能资产、段落和窗口属性三栏编辑
3. 支持段落新增、删除、排序与 Undo / Redo
4. 支持时间轴显示、拖拽、缩放和帧吸附
```

### 阶段 5：预览与数据扩展

```text
1. 增加 AnimationMode 动画采样与播放头
2. 增加 Hitbox 场景预览
3. 按真实需求增加 Motion、Vfx、Invincible 等数据
4. 出现技能分支需求后再评估节点图
```

## 七、当前未决问题

需要后续确认的问题：

```text
1. SpecialSkill 和 Ultimate 的动画路径命名
2. 普攻是否允许移动输入影响朝向
3. 普攻期间是否允许 Dodge 取消
4. SpecialSkill 是否与普攻共用同一种段落推进规则
5. 多 Hitbox 技能使用稳定 Id、枚举还是配置引用进行选择
```

当前已确认：

```text
NormalAttack 动画路径：Base Layer.Skill.normalAttack01
Dodge 不进入 Skill
普攻属于 Skill
第一版不引入 Odin
普通 Inspector 使用 Tri Inspector `1.15.1` 辅助分组、折叠与条件显示
技能编辑器使用 Unity 内置 UI Toolkit，不新增第三方插件
命中、阶段推进与移动锁定窗口由 AbilityWindowConfigSO 按动画统一管理，轨道作为可序列化数据内嵌，不再创建独立 SO
CombatHitbox 已作为通用运行时命中检测组件
运行时推进类型正式命名为 PlayerSkillController
状态动画段落阶段正式命名为 AbilityStepPhase
```
