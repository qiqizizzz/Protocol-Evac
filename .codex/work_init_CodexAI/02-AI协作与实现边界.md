# 02-AI协作与实现边界

## 一、文档目的

本文档用于记录 AI 在本项目中协作编码时必须遵守的实现边界。

## 二、禁止过度安全化判空

禁止写这种把多个必要引用混在一起的总判空：

```csharp
if (m_characterController == null
    || m_animator == null
    || MoveConfig == null
    || ViewConfig == null
    || m_viewRoot == null
    || m_playerCamera == null)
{
    QLog.Error("玩家初始化失败：必要引用缺失，请检查 CharacterController、Animator、MoveConfig、ViewConfig、ViewRoot 与 PlayerCamera");
    return;
}
```

必要引用缺失时，应在具体获取位置暴露具体问题，不要额外写一个总判空兜底。

例如：

```csharp
m_characterController = this.GetOwnerComponent<CharacterController>();
m_animator = this.GetChildComponent<Animator>();
m_viewRoot = this.FindChild(VIEW_ROOT_PATH);
m_playerCamera = this.FindChildComponent<Camera>(PLAYER_CAMERA_PATH);
```

组件或节点缺失时，由 `GetOwnerComponent`、`GetChildComponent`、`FindChild`、`FindChildComponent` 等具体获取方法自己记录明确错误。

## 三、保留简洁方法签名

方法参数较少、单行可读性足够时，应优先保留单行方法签名，不要擅自改成一行一个参数的折叠格式。

推荐：

```csharp
public void Init(PlayerContext context, PlayerViewConfigSO viewConfig, Transform viewRoot, Camera playerCamera)
```

不推荐无必要地改成：

```csharp
public void Init(
    PlayerContext context,
    PlayerViewConfigSO viewConfig,
    Transform viewRoot,
    Camera playerCamera)
```

只有当参数过多、单行明显影响阅读，或当前文件已有统一的多行签名风格时，才考虑拆行。

## 四、内部 Init 不写重复防御式判空

由 `PlayerController`、`EnemyBrain` 或 Binder / Resolver 等内部装配流程调用的 `Init(...)`，其依赖来源应由上层初始化流程和具体获取方法保证，不要在每个 `Init(...)` 中重复添加防御式判空、`QLog.Error` 和 `return`。

不推荐：

```csharp
public void Init(PlayerStateMachine stateMachine, IReadOnlyDictionary<PlayerStateId, PlayerAnimRule.ResolveHandler> handlers)
{
    if (stateMachine == null)
    {
        QLog.Error("初始化玩家动画参数解析器失败：PlayerStateMachine 为空");
        return;
    }

    if (handlers == null)
    {
        QLog.Error("初始化玩家动画参数解析器失败：动画规则集合为空");
        return;
    }

    m_stateMachine = stateMachine;
    m_handlers = handlers;
}
```

推荐：

```csharp
public void Init(PlayerStateMachine stateMachine, IReadOnlyDictionary<PlayerStateId, PlayerAnimRule.ResolveHandler> handlers)
{
    m_stateMachine = stateMachine;
    m_handlers = handlers;
}
```

如果依赖来自场景层级、Inspector 配置、资源加载或外部输入，应在具体获取位置记录明确错误；如果只是内部模块之间的装配参数，不要层层补重复判空逻辑。
